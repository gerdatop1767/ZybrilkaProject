### Problems / NEEDS_REVIEW

- **№15** — математический ответ независимо проверен и корректен, но это «проколотый» промежуток (интервал с одной исключённой точкой, `x ≠ log₅8`). В проекте пока нет согласованного текстового формата для такого ответа, а `packages/shared/src/answerChecker.ts` не умеет надёжно сверять подобную запись — риск несправедливо засчитать верный ответ ученика как неверный (или наоборот). **Не публикуется**, пока формат ответа не будет согласован.
- **№19** — три независимых под-ответа (а/б/в), а текущий Task Engine поддерживает только одно поле ввода на задание. Подгонять три ответа под один текстовый инпут значило бы исказить формат задания. **Не публикуется**, пока не появится поддержка составных (`multi_part`) заданий — заведено как `unsupportedAnswerType`.

Оба случая — это ограничения **текущей архитектуры проверки ответов**, а не ошибки в математике: оба варианта решены и перепроверены (для №19 — сплошным компьютерным перебором всех целых значений ячеек в допустимых диапазонах).

## OCR / рисунки — как проверялись

Текст каждого задания прочитан напрямую с отрендеренных страниц PDF (300 DPI), визуально сверен построчно — ни один текстовый фрагмент не был взят "как есть" из слепого OCR без сверки с изображением страницы. Особое внимание — заданиям 8 и 11, у которых сам график несёт необходимую для решения информацию:

- **Задание 8** (график `y=f'(x)`, найти число точек максимума на `[−18;1]`): чтобы не полагаться на визуальную оценку "на глаз", сетка графика была откалибрована пиксель-в-пиксель (обнаружены реальные линии сетки на изображении, сопоставлены с подписанными на графике значениями `−22`, `0`, `1`, `2`), после чего все точки пересечения кривой с осью `Ox` в интересующем диапазоне были найдены математически (интерполяцией по пикселям), а не оценены глазом. Итог — ровно 2 точки, где производная меняет знак с "+" на "−" внутри `[−18;1]` (x≈−13 и x≈−3); остальные "горбы" графика не пересекают ось и потому не дают экстремумов.
- **Задание 11** (парабола `f(x)=ax²+bx+c`, найти `f(3)`): та же пиксель-калибровка сетки подтвердила, что оба корня параболы отмечены точками ровно на `x=−4` и `x=−1`, а третья отмеченная точка — ровно `(0;4)`. Отсюда `f(x)=(x+4)(x+1)`, `f(3)=28`.

Оба графика вырезаны из оригинального PDF (без перерисовки от руки) и сохранены как обычные PNG-изображения в `apps/web/public/tasks/imports/ege-2026-variant-1/`, подключены к соответствующим заданиям через существующее поле `tasks.imageUrl` и реально отображаются на экране задания (см. `apps/web/src/screens/Task/TaskDesktop.tsx` и `TaskMobile.tsx`).

Никаких дробей/степеней/знаков, вызывающих сомнение, в тексте остальных 17 заданий не обнаружено — исходный текст (`rawStatement`) и нормализованный (`conditionMd`) в БД идентичны для всех заданий, кроме №8 и №11, где `conditionMd` — это чистый текст условия без описания графика (сам график передаётся через `imageUrl`), а `rawStatement` сохраняет пометку `[график]`/`[график: ...]`, честно отражающую, что в оригинале было изображение.

## Pipeline

```
PDF (предоставлен пользователем)
  → RAW (визуальное чтение страниц 1-4, без слепого OCR)
  → PARSE (текст каждого задания вручную сверен с изображением страницы)
  → NORMALIZE (conditionMd; для №8/№11 — отдельно текст + imageUrl)
  → CLASSIFY (subject=math, topic по стандартной номенклатуре номеров ЕГЭ, difficulty по Части 1/2)
  → ANSWER DETECTION (эталонный ответ пособия, если стандартный формат)
  → INDEPENDENT SOLVE (для каждого задания — самостоятельное решение "с нуля", для №8/№11 — пиксель-калиброванное чтение графика, для №19 — компьютерный перебор)
  → EXPLANATION (пошаговое: дано → идея → шаги → ответ)
  → EXPLANATION VALIDATION (повторная проверка каждого шага против условия и verified answer)
  → DEDUPLICATION (sha256 от subject+taskNumber+нормализованное raw-условие, уникальный индекс в БД)
  → DRAFT/PUBLISH GATE (needs_review для №15, №19; published — для остальных 17)
```

Реализация: `packages/db/src/importEge2026Variant1.ts` (идемпотентный импорт, как и `seed.ts`), тесты — `packages/db/src/importEge2026Variant1.test.ts` и `apps/api/src/modules/tasks/importedVariant1.test.ts`. Manifest — `docs/imports/ege-2026-variant-1-manifest.json` (сгенерирован из реально записанных в БД строк, не отдельно от кода).
